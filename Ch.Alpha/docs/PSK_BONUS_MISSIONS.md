# 먼저 끝난 팀을 위한 미션

한 번에 하나만 선택합니다. 모든 조가 같은 난이도를 마칠 필요는 없습니다. 점수는 코드 분량이 아니라 결과를 설명하는 근거로 판단합니다.

## 미션 A · 생산 공간 검토 (10분, 코드 작성 없음)

- 시작: `05_layout_variants.usda`, `07_layout_variant.py`.
- 파일의 Variant 선택값을 compact/wide로 바꾸어 두 배치를 비교합니다.
- 완료: 두 화면과 “작업자 통로 / 설비 간격 중 무엇을 더 확인해야 하는가?” 한 문장.
- 복구: 체크포인트 재열기. 간격이 넓다고 안전 규격을 충족한다고 단정하지 않습니다.

## 미션 B · 원인을 맞혀라 (10~15분, GUI)

- 시작: `03_physics.usda`. 조작자는 동료가 보지 않는 동안 Workpiece의 rigidBodyEnabled를 False로 바꿉니다.
- 관찰자는 Play 결과를 보고 Ground Collider 오류와 어떻게 다른지 설명합니다.
- Stop 후 True로 복구합니다. 이번에는 질량만 1→5kg로 바꾸어 낙하를 비교합니다.
- 완료: “멈춤 / 통과 / 질량 변경” 세 현상을 원인과 연결. 원본은 저장하지 않습니다.

## 미션 C · 정상 수치인데 왜 회색일까? (20분)

- 시작: `08_multi_equipment.usda`, `10_multi_equipment.py` 실행.
- 2초 E03의 UNKNOWN, 6초 E02의 STALE을 출력 또는 `outputs/multi_equipment_report.csv`에서 찾습니다. 화면 변화가 빠르면 CSV를 기준으로 기록합니다.
- CSV에서 빈 값과 sample_time_s를 확인합니다. 수치를 0으로 임의 채우지 않습니다.
- 완료: 총 12행, 마지막 E01=NORMAL/E02=STALE/E03=ALARM을 기록하고 “운영상태와 데이터 신선도를 분리해야 하는 이유”를 설명합니다.
- 복구: `06_stop_tasks.py` 후 장면 재열기. 데이터 판정 이유는 팀원과 설명한 뒤 강사와 확인합니다.

## 미션 D · 운영 개선 제안서 (30분)

- 실습 6의 baseline/hotspot을 같은 범례 20~100°C로 비교합니다.
- 현장 담당자 역할로 “어디를 먼저 확인할지 / 어떤 실제 측정이 필요한지 / 현재 데이터로 판단 못 하는 것”을 각 한 문장 작성합니다.
- 완료: 화면 2개, 합성 데이터 출처, 점검 제안 3문장. 팀원에게 2분 발표.
- 생각해 보기: 색이 진하다는 이유만으로 실제 장비 고장이나 CAE 정확도를 판단할 수 있나요?
