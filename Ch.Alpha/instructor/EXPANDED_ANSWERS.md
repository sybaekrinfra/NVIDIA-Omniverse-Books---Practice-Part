# 확장 실습 강사 해설

질문을 먼저 제시하고 관찰 뒤에 답을 설명합니다. 코드 실행 성공과 학습 목표 달성을 구분합니다.

## D1P1

질문: 형상이 정교하면 Digital Twin의 상태 값도 실제 값인가?

예상 답: 아니다. 형상의 출처와 상태 데이터의 출처는 별개이며 이번 값은 합성 데이터이다.

진행: 기본 6분 + 확장 4분.

확인할 증거: 객체별 역할표와 실제 연동에 필요한 입력 목록.

오류 시 안내: CSV 값의 source를 확인하고 합성 데이터라고 표시한다.

## D1P2

질문: 화면에서 작아진 물체의 Scale도 반드시 작아졌는가?

예상 답: 아니다. 카메라 거리와 시야각만 바뀌어도 화면 크기가 달라진다. Property 수치로 확인한다.

진행: 기본 12분 + 확장 8분.

확인할 증거: 카메라 이동/객체 이동의 수치 비교표.

오류 시 안내: Stage에서 정확한 Prim을 선택하고 Translate를 읽는다.

## D1P3

질문: Xform은 항상 보이는 형상인가?

예상 답: 아니다. Xform은 변환과 계층을 구성하며 보이는 자식 Mesh나 Shape가 별도로 있을 수 있다.

진행: 기본 10분 + 확장 5분.

확인할 증거: 파일 경로/Prim 경로/Attribute 이름 분류표.

오류 시 안내: Stage 내부 경로는 /World로 시작하는 Prim 경로를 사용한다.

## D1P4

질문: Variant를 바꿨는데 위치가 그대로라면 무엇을 확인할까?

예상 답: Variant 바깥에 같은 속성의 더 강한 local opinion을 작성했는지 확인한다. 체크포인트를 다시 열어 비교한다.

진행: 기본 24분 + 확장 14분.

확인할 증거: 두 배치 화면과 좌표 비교.

오류 시 안내: 05 체크포인트를 열고 Variant 이름을 출력한다.

## D1P5

질문: metersPerUnit=1만 확인하면 실물 크기 검수가 끝나는가?

예상 답: 아니다. 내부 좌표와 Scale도 영향을 준다. 기준 치수와 바운드를 비교해야 한다.

진행: 기본 25분 + 확장 20분.

확인할 증거: 오류 수치·원인·수정 수치의 3열 기록.

오류 시 안내: 카메라 대신 경계 크기와 Scale 수치로 판단한다.

## D1P6

질문: Git 파일 이력과 Nucleus Live Session은 같은 기능인가?

예상 답: 아니다. Git은 파일 버전 관리이고 Nucleus/Live는 서버·앱의 공유 및 세션 기능이다. 사용 환경과 검증 절차가 다르다.

진행: 기본 32분 + 확장 20분.

확인할 증거: 담당 Layer 표, 합성 화면, 이동 후 재열기 결과.

오류 시 안내: 의존 폴더 전체를 함께 전달한다.

## D2P1

질문: 모든 항목 PASS면 실제 장비의 동작이 검증된 것인가?

예상 답: 아니다. 이 검사는 제한된 USD 속성의 존재와 값만 확인한다. 런타임 동작과 실제 장비 모델의 타당성은 별도 검증이다.

진행: 기본 8분 + 확장 7분.

확인할 증거: 02와 03의 진단 결과 비교표.

오류 시 안내: 정적 검사와 Play 관찰을 별도 증거로 기록한다.

## D2P2

질문: CAD 전체에 Rigid Body를 한꺼번에 추가하면 무엇이 문제가 될까?

예상 답: 기존 계층과 물리 구조가 충돌하거나 불필요한 동적 객체가 늘 수 있다. 이번에는 작업물에만 적용한다.

진행: 기본 18분 + 확장 12분.

확인할 증거: 원본 CAD와 공통 장면의 활성 물리 대상 비교.

오류 시 안내: 원본을 재복사하고 수정은 상위 Layer에서 수행한다.

## D2P3

질문: A와 B는 질량이 다른데 왜 비슷하게 떨어질까?

예상 답: 공기 저항 없는 동일 중력에서 자유낙하 가속도는 질량에 의존하지 않는다. C는 초기 높이가 달라 낙하 시간이 길다.

진행: 기본 9분 + 확장 6분.

확인할 증거: 예측·관찰·설명 세 항목.

오류 시 안내: 정량 비교에는 시뮬레이션 시간과 측정 방법이 필요함을 설명한다.

## D2P4

질문: Collider API가 붙어 있는데도 통과할 수 있는가?

예상 답: 가능하다. collisionEnabled가 False이면 비활성 상태이다. 스키마 적용 여부와 활성값을 함께 확인한다.

진행: 기본 15분 + 확장 8분.

확인할 증거: 증상·원인·수정 속성·재검증 결과.

오류 시 안내: Stop 후 다시 실행한다.

## D2P5

질문: 실행할 때마다 6개씩 추가되는 것과 최종 6개를 유지하는 것 중 재실행에는 무엇이 유리할까?

예상 답: 같은 입력에서 같은 개수를 만드는 방식이 검증하기 쉽다. 이 함수는 교육용 Batch 경로만 교체한다.

진행: 기본 18분 + 확장 12분.

확인할 증거: 6개/12개 화면, 경로 목록, 재실행 개수.

오류 시 안내: 07 전용 체크포인트를 사용하고 기존 작업을 보존한다.

## D2P6

질문: CSV가 생성되면 낙하 검증을 모두 통과한 것인가?

예상 답: 아니다. 스크립트가 기록한 항목과 실제 물리 관찰이 일치하는지 별도로 확인해야 한다.

진행: 기본 10분 + 확장 5분.

확인할 증거: 실행 CSV와 사람이 작성한 관찰 열.

오류 시 안내: 보고서의 각 열이 무엇을 기록하는지 설명한다.

## D2P7

질문: 마지막 수치가 정상이라면 오래된 데이터도 녹색으로 표시해도 될까?

예상 답: 그렇게 단정할 수 없다. 현재 시각과 샘플 시각의 차이를 검사하고 허용 지연을 넘으면 STALE로 표시한다.

진행: 기본 30분 + 확장 22분.

확인할 증거: 12행 보고서 또는 온도장 비교 화면, 범례, 데이터 출처.

오류 시 안내: UNKNOWN 상태로 표시하고 이전 숫자는 Block하여 남지 않게 한다.
